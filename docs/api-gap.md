# 电商接口缺口分析(管理后台 + H5 + 小程序)

> 目标:对比"管理后台 + H5 + 小程序"三端商城所需接口,盘点当前 NestJS 项目已具备与缺失的能力,按优先级排序。
> 状态标记:`[ ]` 待开发 / `[x]` 已完成

## 一、已有接口(15 个模块)

| 模块 | 能力 | 使用端 |
|---|---|---|
| auth / users | 注册、登录(JWT+bcrypt)、个人资料、改密码 | H5 / 小程序 |
| products / admin/products | 商品列表(搜索/分类/价格/排序/分页)、详情、后台 CRUD | 三端 |
| categories / admin/categories | 分类树、后台 CRUD | 三端 |
| brands | 品牌树 + CRUD(前后台共用) | 管理后台 / H5 |
| cart | 加购 / 改数量 / 删项 / 清空 | H5 / 小程序 |
| orders / admin/orders | 购物车结算下单(事务+行锁)、列表、详情、**模拟支付**、后台改状态 | 三端 |
| addresses | 收货地址 CRUD(含默认地址) | H5 / 小程序 |
| regions | 省市区列表(按 parentCode 层级) | 三端 |
| favorites | 收藏 / 取消收藏 / 分页列表 | H5 / 小程序 |
| comments | 商品评论 / 取消评论 / 我的评论 | H5 / 小程序 |
| sellers | 商家 CRUD | 管理后台 |

## 二、P0 — 缺失即无法上线(必须优先)

| 编号 | 缺口接口 | 说明 | 主要端 |
|---|---|---|---|
| [ ] P0-1 | 商品 SKU / 规格体系 | 现有 product 实体只有单一 price/stock,缺规格(颜色/尺寸/内存)、规格价、规格库存、规格图、SPU→SKU 两级结构 | 三端 |
| [ ] P0-2 | 商品多图 + 富文本详情 | 现有商品仅一张 imageUrl,缺轮播图列表、详情图文 | H5 / 小程序 |
| [ ] P0-3 | 库存扣减 / 防超卖 | 下单时无库存校验与扣减,存在超卖风险(需在 orders 下单链路接入) | 三端 |
| [ ] P0-4 | 文件 / 图片上传 | 全项目无 upload,缺 `FileInterceptor` 上传接口 + `/uploads` 静态托管(品牌 logo、商品图、用户头像均需要) | 管理后台 |
| [ ] P0-5 | 微信小程序登录 | 缺 `code2session` 换 openid、微信手机号授权登录、unionid 绑定 | 小程序 |
| [ ] P0-6 | 微信支付对接 | 仅模拟支付,需微信支付 V3(小程序 JSAPI / H5)+ 异步回调 notify + 验签 | 三端 |
| [ ] P0-7 | 取消订单 + 超时自动关单 | 缺取消接口、缺"未支付 30 分钟自动关闭并回滚库存"定时任务 | H5 / 小程序 |
| [ ] P0-8 | 商品评价列表(游客视角) | 现有 comments 只有"我的评论",缺按商品查询评价列表(详情页展示评分/评价) | H5 / 小程序 |
| [ ] P0-9 | 首页 Banner / 推荐位 | 缺轮播图、运营位配置接口及后台管理 | 三端 |

## 三、P1 — 核心体验(上线后尽快补齐)

| 编号 | 缺口接口 | 说明 | 主要端 |
|---|---|---|---|
| [ ] P1-1 | 退款 / 退货 / 售后 | 售后申请单、后台审核、退款记录(order 实体缺 refund 相关字段) | 三端 |
| [ ] P1-2 | 确认收货 / 订单完成 | 订单缺"已发货 → 确认收货"状态流,无发货运单号字段 | H5 / 小程序 |
| [ ] P1-3 | 优惠券 | 领券、我的券、下单抵扣(金额门槛校验)、后台发券配置、幂等领取 | 三端 |
| [ ] P1-4 | 后台用户管理 | admin/ 下仅 categories/orders/products,缺用户列表、详情、禁用 | 管理后台 |
| [ ] P1-5 | 数据看板 | 今日 GMV、订单数、新增用户、TOP 商品、近 7 日趋势(QueryBuilder 聚合) | 管理后台 |
| [ ] P1-6 | 手机号登录 / 短信验证码 | H5 通用登录方式(视业务是否需要) | H5 |
| [ ] P1-7 | Token 刷新 / 登出 | 现有一次性 JWT,缺 refresh token 机制 | 三端 |

## 五、建议开发顺序

```
第一步(P0 闭环): P0-4 文件上传 → P0-1 SKU/多图 → P0-3 库存扣减 → P0-5 小程序登录 → P0-6 微信支付 → P0-7 取消/超时关单 → P0-8 评价列表 → P0-9 Banner
第二步(P1 留存):   P1-3 优惠券 → P1-1 售后/退款 → P1-2 确认收货 → P1-4 用户管理 → P1-5 数据看板 → P1-7 token 刷新
第三步(P2 增强):   P2-1 营销活动 → P2-3 物流 → P2-4 通知 → P2-5 RBAC → P2-2 评论管理 → P2-6 搜索增强
```

**验收口径**:每组任务完成后 `npm run build` 无错误、Swagger 文档完整、curl 正常流 + 异常流各验证一遍。
